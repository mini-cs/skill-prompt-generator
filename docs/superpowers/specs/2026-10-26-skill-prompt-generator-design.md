# 개발자 프롬프트 생성기 — 설계 스펙

- 작성일: 2026-10-26
- 상태: 사용자 검토 대기
- 프로젝트 폴더: `skill-prompt-generator/` (화면 제목은 "개발자 프롬프트 생성기")

---

## 1. 목적

사용자가 만들고 싶은 Claude Skill의 아이디어와 조건을 폼에 입력하면, SKILL.md 설계를 요청하는 **완성 프롬프트를 조립**해 준다. 사용자는 이 프롬프트를 복사해 Claude 채팅에 붙여넣는다. 페이지는 AI를 직접 호출하지 않는다.

**사용자:** 본인(개발 직무 준비 중, 반복 업무를 스킬로 만들 때 사용). 동기에게 프로젝트째로 공유할 수 있다.

**구현 방식:** 사용자가 VS Code의 Claude Code로 프로젝트를 생성한다. 이 스펙과 구현 계획 문서가 Claude Code에 넘기는 입력이다.

**성공 기준**

1. [예시로 채우기] → [프롬프트 복사] → Claude에 붙여넣기만으로, 설치·테스트까지 가능한 SKILL.md 설계를 받을 수 있다.
2. 생성된 프롬프트에 대상 플랫폼의 공식 규칙과 어긋나는 지시가 없다. (판단 기준: §4 검증된 사실)
3. 새 기능을 추가할 때 기존 기능 파일을 수정하지 않는다. (기능 폴더 추가 + `features/registry.js`에 1줄 등록)

---

## 2. 범위

**포함**

- 상세 입력 폼(섹션 3개, 접기/펼치기)과 실시간 미리보기
- 예시로 채우기 / 초기화
- 입력 검사: 스킬 이름 규칙, Bash 패턴 형식, 아이디어 필수
- 트리거 글자 수 카운터
- 대상 플랫폼에 따른 칸 활성/비활성
- 복사(실패 시 전체 선택으로 대체)
- 자동 임시 저장
- [예시로 채우기]·[초기화] 후 5초간 되돌리기
- 섹션 접기/펼치기와 접힌 섹션의 입력 개수 표시
- 모바일 하단 고정 복사 바

**제외 (필요해지면 기능 폴더로 추가)**

- AI 호출(페이지가 Claude를 직접 부르는 기능)
- 페이지에서 SKILL.md 파일을 직접 생성·다운로드
- claude.ai 링크 발행용 단일 파일 빌드
- 그 밖의 Claude Code 전용 frontmatter 필드: `arguments`, `context`, `agent`, `model`, `effort`, `hooks`, `paths`, `disallowed-tools` 등
- 스프링 애니메이션 라이브러리, 제스처 기법, 소리·진동 피드백 (§3-3)

## 3. 화면 구성과 디자인

디자인은 사용자가 첨부한 `apple-design` 스킬을 기준으로 한다. 단, 이 도구에 해당하는 원칙만 골라 아래 값으로 정한다. 아래 수치는 모두 이 프로젝트에서 정한 값이다.

### 3-1. 레이아웃 (접근안 C: 한 페이지 폼 + 실시간 미리보기 + 예시로 채우기)

- **상단 바(고정):** 제목 "개발자 프롬프트 생성기", "자동 저장됨" 상태 표시, [예시로 채우기], [초기화]
- **본문:** 최대 너비 72rem. 왼쪽에 폼, 오른쪽에 미리보기와 [프롬프트 복사] 버튼. 미리보기 패널은 스크롤해도 상단 바 아래에 붙어 따라오고(sticky), 내용이 길면 패널 안에서 스크롤된다.
- **너비 900px 미만:** 한 열로 바뀌고, 미리보기는 폼 아래로 내려간다. 화면 하단에 반투명 고정 바([프롬프트 복사] + 복사를 막는 문제 개수)를 둔다.
- **UI 언어:** 한국어
- **서버 없이 열었을 때:** `file://`로 열면 ES 모듈이 로드되지 않는다. 그래서 "로컬 서버로 열어주세요(README 참고)" 안내를 HTML에 기본으로 보이게 두고, `main.js`가 정상 로드되면 숨긴다.

### 3-2. 적용하는 디자인 원칙

**즉각 반응**

- 버튼은 누르는 순간(`:active`) `scale(0.97)`, 100ms ease-out으로 반응한다. 손을 뗄 때가 아니다.
- 미리보기는 입력할 때마다 바로 갱신한다. 디바운스(입력이 멈출 때까지 기다리는 것)를 두지 않는다. 자동 저장의 300ms 대기는 화면 피드백이 아니라 저장 시점이라서 예외다.
- 버튼과 입력칸에 `touch-action: manipulation`을 준다. 모바일 더블탭 확대 대기를 없애기 위해서다.
- 버튼 등 누르는 대상은 높이를 최소 2.75rem(44px)으로 한다.

**재질과 깊이**

- **상단 바·모바일 하단 바:** 반투명 + `backdrop-filter: blur(20px) saturate(180%)`. 배경은 라이트 `rgba(255,255,255,0.72)`, 다크 `rgba(28,28,30,0.72)`. 내용이 바 아래로 스크롤된다.
- **폼·미리보기 패널:** 불투명한 패널 색. 반투명 위에 반투명을 겹치지 않는다.
- **상단 바 아래 구분선:** 고정 구분선은 없다. 페이지가 스크롤되어 내용이 바 아래로 들어갔을 때만 옅은 그림자를 150ms 페이드로 보여준다.
- **패널 그림자:** 라이트 `0 1px 2px rgba(0,0,0,.04), 0 4px 16px rgba(0,0,0,.06)`. 다크는 그림자 대신 배경과 패널의 명도 차이로 구분한다.

**색상 (라이트 / 다크)**

- 배경: `#f5f5f7` / `#000000`
- 패널: `#ffffff` / `#1c1c1e`
- 기본 글자: `#1d1d1f` / `#f5f5f7`
- 보조 글자: `#6e6e73` / `#a1a1a6`
- 구분선: `rgba(0,0,0,.1)` / `rgba(255,255,255,.12)`
- 강조(버튼·포커스 테두리): `#0071e3` / `#2997ff`
- 완료: `#248a3d` / `#30d158`
- 경고: `#c93400` / `#ff9f0a`
- 오류: `#d70015` / `#ff453a`
- 시스템 설정(`prefers-color-scheme`)을 따른다. 테마가 바뀔 때 배경색과 글자색은 200ms에 걸쳐 바뀐다.

**타이포그래피**

- **본문 글꼴:** `system-ui, -apple-system, "Apple SD Gothic Neo", "Malgun Gothic", sans-serif` (외부 폰트 없음)
- **미리보기 글꼴:** `ui-monospace, SFMono-Regular, Menlo, Consolas, monospace`
- **크기 / 굵기 / 줄간격 / 자간 세트:**
  - 페이지 제목: 1.75rem / 700 / 1.15 / -0.02em
  - 섹션 제목: 1.0625rem / 600 / 1.3 / -0.01em
  - 라벨: 0.875rem / 600 / 1.4 / 0
  - 본문·입력칸: 1rem / 400 / 1.5 / 0
  - 도움말·오류: 0.8125rem / 400 / 1.45 / 0.01em
  - 미리보기: 0.875rem / 400 / 1.6 / 0
- **간격:** rem 단위만 쓴다. 0.25 · 0.5 · 0.75 · 1 · 1.5 · 2
- **모서리:** 패널 1rem, 입력칸·버튼 0.625rem

**피드백 4종류**

- **상태:** 상단 바에 "자동 저장됨"을 보조 글자색으로 표시
- **완료:** [프롬프트 복사] 버튼 글자가 1.5초간 "복사됨 ✓"(완료 색)으로 바뀜
- **경고:** 글자 수가 기준을 넘으면 카운터가 경고 색으로 바뀜
- **오류:** 칸 바로 아래에 오류 색 글씨로 표시. 입력하는 즉시 보여준다.

**움직임** (관성 동작이 없으므로 튕김 없음)

- **기본 곡선:** `cubic-bezier(0.25, 1, 0.5, 1)`. 목표를 넘었다가 돌아오지 않는 감속 곡선이다.
- **움직이는 속성:** `transform`과 `opacity`만 쓴다.
- **섹션 펼침:** 내용이 제목 쪽에서 0.25rem 내려오며 나타난다(200ms). 접을 때는 같은 경로로 올라가며 사라진다. 움직이는 도중에 다시 누르면 그 자리에서 방향을 바꾼다(입력을 막지 않는다).
- **알림:** 아래에서 올라와 나타나고, 아래로 내려가며 사라진다(200ms). 새 알림이 오면 이전 알림을 대체한다.

**접근성 설정**

- **`prefers-reduced-motion: reduce`(움직임 줄이기):** 이동 없이 150ms 불투명도 페이드만 쓴다. 버튼 눌림은 크기 변화 대신 배경색 변화로 표시한다.
- **`prefers-reduced-transparency: reduce`(투명도 줄이기):** 상단·하단 바를 패널 색으로 불투명하게 하고 블러를 뺀다.
- **`prefers-contrast: more`(고대비):** 바를 불투명하게 하고 1px 진한 테두리를 준다. 보조 글자는 기본 글자색으로 바꾼다.
- 알림 영역은 `aria-live="polite"`로 둔다. 섹션 버튼에는 `aria-expanded`를 쓴다. 오류 문구는 `aria-describedby`로 해당 칸과 연결한다.

**구체적인 라벨:** "프롬프트 복사", "예시로 채우기", "초기화", "되돌리기"처럼 무엇을 하는지 정확히 적는다.

### 3-3. 적용하지 않는 것 (과적용 방지)

- **스프링 애니메이션 라이브러리(Motion 등):** "외부 라이브러리 없음" 원칙을 유지한다. 관성 동작이 없어서 CSS 전환으로 충분하다.
- **제스처 기법:** 드래그, 스와이프, 관성 투척(모멘텀), 고무줄 경계는 이 도구에 해당하는 조작이 없어서 쓰지 않는다.
- **소리·진동 피드백**도 쓰지 않는다.

## 4. 검증된 사실 (프롬프트 규칙의 근거)

2026-10-26에 확인했다. 공식 문서가 바뀌면 `js/data/rules.js`만 수정한다.

**출처**

- [A] Claude Code 스킬 문서: https://code.claude.com/docs/es/skills (같은 문서의 스페인어판을 읽음)
- [B] Agent Skills 표준 규격: https://agentskills.io/specification
- [C] claude.ai 도움말 "Use skills in Claude": https://support.claude.com/en/articles/12512180

**사실 목록**

- **F1** [A] Claude Code에서는 `description`과 `when_to_use`를 합친 텍스트가 스킬 목록에서 1,536자로 잘린다. 오류가 아니라 잘림이다. 그래서 핵심 용도를 맨 앞에 둔다.
- **F2** [A] 개인·프로젝트 스킬에서 `/명령어` 이름은 폴더 이름에서 나온다. `name` 필드는 목록에 보이는 라벨이다.
- **F3** [A] 설치 경로는 개인용 `~/.claude/skills/<스킬명>/SKILL.md`, 프로젝트용 `.claude/skills/<스킬명>/SKILL.md`다.
- **F4** [A] `$ARGUMENTS`는 인자 전체다. `$ARGUMENTS[N]`과 `$N`은 0부터 센다. 즉 `$0`이 첫 번째 인자다.
- **F5** [A] `argument-hint`는 자동완성 때 보여주는 인자 힌트다. Claude Code 전용이다.
- **F6** [A] `allowed-tools`는 스킬을 호출한 그 턴에만 승인 없이 쓰게 해주고, 다음 메시지에서 해제된다. 목록에 없는 도구를 막지는 않는다. 공백·쉼표로 구분한 문자열이나 YAML 리스트로 쓴다.
- **F7** [A] `disable-model-invocation: true`면 사용자만 호출할 수 있고, `user-invocable: false`면 Claude만 호출할 수 있다.
- **F8** [A] claude.ai 업로드와 Skills API는 `name`, `description`, `license`, `compatibility`, `metadata`, `allowed-tools` 6개 필드만 허용한다. 그 외 필드가 있으면 업로드가 실패한다. Claude Code도 이 6개 필드를 받는다.
- **F9** [B] `name`은 1~64자, 소문자·숫자·하이픈만 쓸 수 있다. 하이픈으로 시작·끝날 수 없고, `--` 연속도 안 되며, 상위 폴더 이름과 같아야 한다. `description`은 1~1,024자다.
- **F10** [A] SKILL.md는 500줄 이하로 유지하고, 자세한 자료는 별도 파일로 나누는 것을 권장한다.
- **F11** [A] 테스트는 새 세션에서 한다. 스킬을 만들던 대화에 남은 맥락이 지시문의 빈틈을 가리기 때문이다.
- **F12** [C] claude.ai에는 스킬 폴더를 ZIP으로 묶어 업로드한다. 코드 실행 기능이 켜져 있어야 한다. 폴더 이름이 스킬 이름과 다르면 업로드가 실패할 수 있다. 메뉴 위치는 도움말 문서 버전마다 표기가 달라서 경로를 고정하지 않고 [C] 링크로 안내한다.

**미검증 (프롬프트에 사실로 넣지 않음)**

- claude.ai에서 `$ARGUMENTS` 같은 인자 치환이 동작하는지는 확인하지 못했다. → 인자 칸은 Claude Code를 골랐을 때만 활성화한다.

## 5. 입력 폼 명세

**표기 규칙:** 칸 이름(상태 키) — 입력 형태 — 활성 조건 — 설명

**섹션 열림 기본값:** 섹션 1은 펼친 상태, 섹션 2·3은 접힌 상태로 시작한다. 접힌 섹션 제목 옆에는 활성 칸 중 값이 있는 칸 수를 "N개 입력됨"으로 표시한다. [예시로 채우기]를 누르면 세 섹션 모두 펼친다.

### 섹션 1. 기본

- **아이디어 (`idea`)** — 여러 줄 입력, 필수 — 항상 활성 — 비어 있으면 복사를 막고 "아이디어를 먼저 적어주세요"를 표시한다.
- **대상 플랫폼 (`platform`)** — 라디오: `claude-code`(기본) / `claude-ai` / `both` — 항상 활성 — 아래 칸들의 활성 여부와 프롬프트의 규칙 블록을 결정한다.
- **스킬 이름 후보 (`skillName`)** — 한 줄 입력, 선택 — 항상 활성 — F9 규칙으로 실시간 검사한다. 위반하면 이유를 표시하고 복사를 막는다. 비워두면 Claude가 이름을 제안하도록 한다.

### 섹션 2. 동작

- **호출 방식 (`invocation`)** — 라디오: `both`(기본) / `user-only` / `model-only` — `claude-code`일 때만 활성 — F7에 대응한다.
- **트리거 상황 (`triggers`)** — 여러 줄 입력 — 항상 활성 — 글자 수 카운터를 단다. 기준은 `claude-code` 1,536자, `claude-ai`·`both` 1,024자다. 넘으면 경고색만 표시하고 복사는 막지 않는다.
- **인자 (`argMode`)** — 라디오: `none`(기본) / `whole` / `split` — `claude-code`일 때만 활성.
- **인자 이름 (`argNames`)** — 한 줄 입력, 쉼표로 구분 — `claude-code`이고 `argMode = split`일 때만 활성 — 칸 아래에 `$0 = 경로, $1 = 형식` 같은 대응표를 보여준다.
- **허용 도구 (`tools`)** — 체크박스: Read, Grep, Glob, Edit, Write — 항상 활성(F8 허용 필드) — 옆에 F6 도움말을 표시한다.
- **Bash 패턴 (`bashPatterns`)** — 한 줄 입력, 쉼표로 구분 — 항상 활성 — 항목마다 `Bash(내용)` 형식인지 검사한다. 틀리면 "Bash(명령 *) 형태로 적어주세요"를 표시하고 복사를 막는다.

### 섹션 3. 예시·금지사항

- **입력 예시 (`inputExample`)** — 여러 줄 입력 — 항상 활성
- **기대 출력 예시 (`outputExample`)** — 여러 줄 입력 — 항상 활성
- **금지사항 (`prohibitions`)** — 여러 줄 입력, 한 줄에 하나 — 항상 활성
- **출력 형식 제약 (`outputConstraints`)** — 여러 줄 입력, 한 줄에 하나 — 항상 활성 — 안내 문구로 "형용사 대신 구체 조건(예: 첫 줄에 총평 1문장, 항목 10개 이하)"을 보여준다.

### 비활성 칸 처리

- 비활성 칸은 회색으로 바뀌고, 이유를 표시한다. 예: "claude.ai에는 없는 기능이라 프롬프트에서 빠져요".
- 입력값은 지우지 않고 상태에 보관한다. 프롬프트에서만 뺀다. 다시 활성화되면 값이 그대로 돌아온다.

## 6. 조립되는 프롬프트 구조

순서는 아래와 같고, 프롬프트 언어는 한국어다.

### 6-1. `# Role (역할)`
원문 문장을 쓰되 대상 표현만 바꾼다. `claude-code`는 "Claude Code용", `claude-ai`는 "claude.ai용", `both`는 "Claude Code와 claude.ai 공용"이다.

### 6-2. `# Task (임무)`
원문 그대로 쓴다.

### 6-3. `# SKILL.md 작성 표준 규칙`

**Frontmatter 규칙 — `claude-code`**

- `name`: F9 규칙을 따르고 폴더 이름과 같게 쓴다. 명령어는 폴더 이름에서 나온다는 설명도 붙인다(F2).
- `description`: 무엇을 하는지와 언제 쓰는지를 쓰고, 핵심 용도를 맨 앞에 둔다. `when_to_use`와 합쳐 1,536자가 넘으면 잘린다(F1).
- `when_to_use`: 트리거 상황이 입력된 경우에만 넣는다.
- `argument-hint`: `argMode`가 `none`이 아닐 때만 넣는다(F5).
- `allowed-tools`: 도구나 Bash 패턴이 하나라도 선택된 경우에만 넣는다(F6).
- `invocation`이 `user-only`면 `disable-model-invocation: true`, `model-only`면 `user-invocable: false`를 넣는다(F7). `both`면 둘 다 넣지 않는다.

**Frontmatter 규칙 — `claude-ai` / `both`**

- 허용 필드 6개만 쓰고 그 외 필드는 쓰지 않는다. 쓰면 업로드가 실패한다(F8).
- `name`은 F9 규칙을 따르고 폴더 이름과 같게 쓴다.
- `description`은 1,024자 이하로 쓰고 핵심 용도를 맨 앞에 둔다(F9).
- `allowed-tools`는 도구가 선택된 경우에만 넣는다.

**Body 규칙 — 공통**

- 단계별(Step-by-step) 실행 워크플로우로 구성한다.
- 형용사적 지시 대신 구체적인 제약 조건을 쓴다(원문 유지).
- SKILL.md는 500줄 이하로 유지하고, 긴 참고 자료는 별도 파일로 분리한다(F10).
- `claude-code`이고 `argMode`가 `none`이 아니면 F4 인자 규칙을 넣는다. `$ARGUMENTS`는 전체, `$0`이 첫 번째다.

### 6-4. `# 사용자 스킬 명세`

활성 상태이면서 값이 있는 칸만, 아래 순서와 라벨로 넣는다.

아이디어 → 대상 → 스킬 이름 후보 → 호출 방식 → 트리거 상황 → 인자(`whole`이면 "`$ARGUMENTS` 전체", `split`이면 "`$0` = …, `$1` = …") → 허용 도구 → 입력 예시 → 기대 출력 예시 → 금지사항 → 출력 형식 제약

마지막 줄에는 항상 이 지시를 넣는다: "명세에 없는 항목은 제안하되, 제안한 값이라고 표시할 것."

### 6-5. `# Output Format (출력 형식)`

1. 스킬 디렉토리 및 파일 구조
2. 복사해서 쓸 수 있는 완성된 SKILL.md 코드(YAML Frontmatter 포함)
3. 설치 방법
   - `claude-code`: F3 경로 두 가지와 "폴더명 = 명령어 이름"(F2)
   - `claude-ai`: 폴더명 = name으로 맞춘 뒤 ZIP으로 압축해 업로드, 코드 실행 기능 필요, 메뉴 위치는 [C] 링크 참고(F12)
   - `both`: 위 두 가지를 모두
4. 테스트 방법: `/명령어` 실행(`claude-code`·`both`), 트리거돼야 하는 문장 2개와 트리거되면 안 되는 문장 1개, 새 세션에서 테스트할 것(F11)
5. 규칙 셀프 체크: `name` 규칙, `description` 글자 수, 허용되지 않은 필드 포함 여부를 항목별 통과/실패로 표시

**설계 합의 이후 바뀐 점 3가지**

- `name-check`를 `field-check`로 바꿨다. Bash 패턴 검사와 아이디어 필수 검사도 한곳에서 맡아야 "복사를 막을지"를 한 기능이 판단할 수 있기 때문이다.
- `js/bind.js`, `js/data/defaults.js`, `README.md`, `package.json`, `CLAUDE.md`를 추가했다.
- `package.json`의 `"type": "module"`은 Node가 `.js` 파일을 ES 모듈로 읽게 하는 설정이다.

### 7-2. 상태 (`store.js`)

`createStore(initial)` 함수는 `{ get, set, subscribe }`를 돌려준다.

- `form`: 5장의 모든 칸 값이다. 자동 저장 대상이다.
- `status.blocking`: 복사를 막는 문제 목록이다. `field-check`만 쓴다.
- `status.prompt`: 조립된 프롬프트 문자열이다. `prompt-builder`만 쓴다.
- `status.toast`: 현재 알림 `{ message, undoForm? }`이다. 새 알림이 오면 이전 알림을 대체한다.
- `status.savedAt`: 마지막 자동 저장 시각이다. `autosave`만 쓴다.
- `ui.openSections`: 섹션별 열림 여부다. `sections`가 화면에 반영하고, `example-fill`이 모두 펼칠 때 쓴다.

`set(patch)`로 바꾸면 구독자 전체에 알린다. `status`와 `ui`는 저장하지 않는다.

### 7-3. 기능 모듈 계약

- 모든 기능 폴더의 `index.js`는 `export function init(ctx)` 하나를 내보낸다.
- `ctx`는 `{ store, root, rules, defaults, example }`이다.
- `registry.js` 항목 형식: `{ name: 'copy', load: () => import('./copy/index.js'), css: true }`
- `bind.js`는 양방향으로 연결한다.
  - 입력칸을 바꾸면 `store`의 `form`을 갱신한다.
  - 반대로 `form`이 바뀌면 입력칸 값도 맞춘다. 이 덕분에 예시 채우기, 초기화, 자동 저장 복원이 화면에 바로 반영된다.
- `main.js`의 동작 순서:
  1. 서버 없이 열었을 때의 안내를 숨긴다.
  2. `defaults.js` 값으로 `store`를 만든다.
  3. `bind.js`로 폼과 `store`를 연결한다.
  4. `registry.js` 순서대로 `css`가 있으면 `<link>`를 추가하고, `load()` 후 `init(ctx)`를 호출한다.
  5. 마지막에 상태를 한 번 알려서 첫 화면을 그린다.
- 등록 순서는 `field-check` → `platform-switch` → `arg-map` → `char-counter` → `prompt-builder` → `sections` → `scroll-edge` → `toast` → `example-fill` → `copy` → `autosave`다. `autosave`를 마지막에 두는 이유가 있다. `init` 때 저장된 값을 복원하면 앞의 기능들이 모두 그 값으로 갱신되기 때문이다.
- 기능끼리 서로를 직접 import하지 않는다. 기능 사이의 정보는 오직 `store`로만 주고받는다.

### 7-4. 데이터 흐름

입력 → `bind.js` → `store.set({ form })` → 구독자 순서대로 실행

- `field-check` → `status.blocking` 갱신
- `platform-switch` → 칸 활성/비활성
- `char-counter` → 카운터 갱신
- `prompt-builder` → `build(form, rules)` → `status.prompt` + 미리보기 갱신
- `sections` → 접힌 섹션의 "N개 입력됨" 갱신
- `autosave` → 300ms 동안 입력이 없으면 저장

[프롬프트 복사]를 누르면 `copy`가 `status.blocking`이 비어 있는지 확인한 뒤 `status.prompt`를 복사한다.

[예시로 채우기]나 [초기화]를 누르면 `example-fill`이 현재 `form`을 보관한 상태로 `status.toast = { message, undoForm }`을 쓰고 `form`을 바꾼다. 사용자가 `toast`의 [되돌리기]를 누르면 `undoForm`으로 `form`을 되돌린다.

### 7-5. 프로젝트 규칙 파일 (`CLAUDE.md`)

나중에 Claude Code로 기능을 추가할 때도 같은 구조를 지키게 하려고 둔다. 아래 내용만 짧게 담는다.

- 외부 라이브러리와 빌드 도구를 쓰지 않는다. HTML·CSS·JS는 파일로 나누고, JS는 ES 모듈로 쓴다.
- 새 기능은 `features/<기능명>/` 폴더 하나로 만든다. `index.js`의 `init(ctx)` 하나만 내보내고, `features/registry.js`에 1줄을 등록한다.
- 기능끼리 직접 import하지 않는다. 정보는 `store`로만 주고받는다.
- 화면과 무관한 로직은 순수 함수 파일로 분리하고 `tests/`에 테스트를 둔다. 변경 후 `npm test`를 실행한다.
- 공식 문서 기반 규칙 문구는 `js/data/rules.js`에만 둔다. 확인되지 않은 규칙은 추가하지 않는다.
- 실행 확인은 로컬 서버로 한다(`python -m http.server 8000`).
- 화면·인터랙션 작업은 `.claude/skills/apple-design` 스킬을 참고하되, 적용 범위와 수치는 스펙 §3-2·§3-3을 따른다. 외부 애니메이션 라이브러리와 제스처 기법은 쓰지 않는다.

## 8. 오류 처리

- **아이디어가 비었을 때:** 복사를 막고 "아이디어를 먼저 적어주세요"를 표시한다.
- **스킬 이름 규칙 위반:** 위반한 규칙마다 이유를 표시하고 복사를 막는다. 예: "대문자는 쓸 수 없어요".
- **Bash 패턴 형식 오류:** 틀린 항목과 올바른 형태를 표시하고 복사를 막는다.
- **트리거 글자 수 초과:** 카운터를 경고색으로 바꾼다. 복사는 허용한다.
- **대상 변경:** 칸을 비활성화하고 이유를 표시한다. 값은 보존한다.
- **클립보드 실패:** 미리보기 전체를 선택하고, 알림으로 "Ctrl+C(맥은 ⌘+C)로 복사하세요"를 표시한다.
- **브라우저 저장소를 쓸 수 없을 때:** 저장을 건너뛰고 나머지 기능은 정상 동작한다.
- **저장된 데이터가 깨졌을 때:** JSON 해석에 실패하면 무시하고 기본값으로 시작한다.
- **[예시로 채우기]·[초기화]:** 확인창 없이 바로 실행한다. 이전 입력을 보관하고 5초 동안 "예시로 채웠어요 [되돌리기]" 또는 "초기화했어요 [되돌리기]" 알림을 보여준다. [되돌리기]를 누르면 이전 입력으로 돌아간다. 5초가 지나거나 다른 알림이 오면 보관본은 버린다.
- **`file://`로 열었을 때:** 3장의 서버 안내가 그대로 보인다.

**`validate.js`**

- 이름 `pr-review` → 통과. 64자 이름 → 통과. 빈 값 → 통과(선택 칸).
- 이름 `PR-Review`(대문자), `-pr`(하이픈 시작), `pr-`(하이픈 끝), `pr--review`(`--` 연속), `pr_review`(허용 안 되는 문자), 65자 이름 → 각각 해당 이유로 실패.
- Bash 패턴 `Bash(git diff *)` → 통과. `git diff *`, `Bash()` → 실패.
- 아이디어가 비었거나 공백뿐이면 → 복사 차단 항목에 들어감.

**`build.js`**

- `claude-code` + 예시 데이터 → Role, 규칙(`argument-hint`·`when_to_use`·1,536 포함), 명세, Output 1~5가 모두 있다.
- `claude-ai` → `argument-hint`·`when_to_use`·`disable-model-invocation` 문구가 없다. 허용 필드 6개 규칙, 1,024, ZIP 설치 안내가 있다.
- `both` → 6개 필드 규칙이 있고, 설치 방법이 두 가지 모두 있다.
- 빈 선택 칸은 명세에서 빠진다. "제안한 값이라고 표시" 지시는 항상 있다.
- `argMode = split`, `argNames = "경로, 형식"` → `$0 = 경로`, `$1 = 형식`이 나온다.
- `claude-ai`인데 `argMode = split`이 보관되어 있는 경우 → 프롬프트에 `$0`이 없다(비활성 값 제외).
- `invocation = user-only` → `claude-code`에서는 `disable-model-invocation: true`가 있고, `claude-ai`에서는 없다.

**`count.js`**

- 섹션별로 값이 있는 활성 칸 수를 센다. 빈 문자열과 공백뿐인 값은 세지 않는다.
- `claude-ai`일 때 비활성인 칸(호출 방식, 인자)은 값이 보관돼 있어도 세지 않는다.

## 11. 전달

이 대화에서는 완성된 코드가 아니라 **Claude Code에 넘길 문서**를 전달한다.

- 설계 스펙: `docs/superpowers/specs/2026-10-26-skill-prompt-generator-design.md` (이 문서)
- 구현 계획: `docs/superpowers/plans/` 아래에 작성 (스펙 승인 후)
- 디자인 스킬: 사용자가 첨부한 `SKILL.md`를 `.claude/skills/apple-design/SKILL.md`에 둔다. 프로젝트 사본에서는 맨 앞의 "Initial Response" 부분을 뺀다. 이 부분은 "질문 없이 호출되면 소개 문장만 답하고 다른 정보는 주지 말라"는 지시라서, 구현 도중 자동으로 불려오면 작업 흐름을 끊을 수 있기 때문이다.

사용자는 VS Code에서 빈 `skill-prompt-generator/` 폴더를 열고, 두 문서를 같은 경로에 넣은 뒤, Claude Code에 구현 계획대로 진행하도록 요청한다.

## 12. 결정 기록

- **사용 흐름 ①(프롬프트 조립 → 붙여넣기):** AI 호출 없이 동작하게 하기 위해서다.
- **상세 폼:** 조건이 구체적일수록 Claude가 추측하는 부분이 줄어들기 때문이다.
- **화면 C(폼 + 실시간 미리보기 + 예시로 채우기):** 반복 수정이 빠르고, 예시가 "칸에 뭘 써야 할지 모르는" 문제를 줄여주기 때문이다.
- **Output에 5번 규칙 셀프 체크 추가:** 사용자 승인.
- **HTML·CSS·JS 분리, 기능 1개 = 폴더 1개:** 사용자 요청.
- **ES 모듈 + 로컬 서버:** 기능을 폴더로 계속 늘려가는 구조와 Node 테스트에 맞기 때문이다. 사용자 선택.
- **템플릿 보정:** 공식 문서 기준으로 고친 버전(§4)을 기본으로 쓴다.
- **구현은 VS Code의 Claude Code로:** 사용자 결정. 그래서 전달물을 "완성 코드 ZIP"에서 "스펙 + 구현 계획"으로 바꿨다.
- **`CLAUDE.md` 추가:** 이후 기능 추가 때도 Claude Code가 폴더 구조 규칙을 지키게 하기 위해서다.
- **디자인은 첨부한 apple-design 스킬 기준:** 사용자 요청. 이 도구에 해당하는 원칙만 수치로 옮겼다(§3-2). 제스처·스프링 라이브러리는 제외했다(§3-3).
- **확인창 대신 되돌리기:** 되돌릴 수 있는 작업이므로 확인창보다 쉬운 되돌리기를 쓴다(apple-design의 Agency 원칙). 사용자 동의.
- **섹션 2·3 접힌 상태로 시작:** 자주 쓰는 경로를 먼저 보여주기 위해서다. 사용자 동의.
- **모바일 하단 복사 바:** 긴 폼을 끝까지 스크롤하지 않고도 복사할 수 있게 하기 위해서다. 사용자 동의.
- **디자인 스킬을 프로젝트에 포함:** Claude Code가 UI 작업 때 직접 참고하게 하기 위해서다. 사용자 동의.
